# 旷野大计算 pro · 计算图工坊

在线试玩：<https://kitakazeshiori.github.io/kuang-ye-da-ji-suan-pro/>

把《连续数学计算图》这道题做成可玩的**可视化计算图编辑器 / 游戏网站**。纯静态、零构建步骤，直接部署到 GitHub Pages 或 Cloudflare Pages。

## 现在有什么

- **无限画布**：拖动/滚轮平移，Ctrl+滚轮或双指缩放，缩放范围 1%–600%，`F` 一键适应内容。
- **nandgame 式节点**：简洁圆角框 + 左侧色条，**输入端口在顶边、输出端口在底边**；框里只写标题，不放功能说明；节点右侧的小三角按钮点开是 `delete` 菜单。
- **工具箱拖拽**：左侧一栏列出 11 种节点（in / const / add / neg / mul / sin / cos / exp / sqrt / **中转**（空节点：输出 = 输入，W0，画布上不写标签，导出时自动省略，只用来理线）/ out，节点标签用英文并在框内居中显示），**直接拖到画布上松手即在落点创建**（触屏同样可用），单击则放在视图中央。权重与题面一致，实时显示加权节点数 W。
- **nandgame 式连线**：从输出端拖到输入端连线；**全图连线常态渲染**（按包围盒裁剪、按颜色批量描边），即使两端节点都在视野外、线只是横穿视野也照画，可以顺着线找到比较远的节点；把已连线的输入端拖走即可断开；拖到空白处松开会弹出菜单，**直接新建节点并自动接线**。
- **数位矩阵（高精度数值组件）**：整数位在上、小数位在下，中间一条分割线；像 Hex Editor 一样按位编辑——单击/拖动选中，输入数字**覆盖当前位并右移**，`Backspace`/`Delete`/剪切让后续数字**整体左移**（不是补 0），粘贴则**整体右移**；支持 `Ctrl+A/C/X/V`、方向键与 `-` 切换符号，小数位完整显示 72 位。
- **常数节点**：框内直接显示数值文本，**双击**打开「文本 + 数位矩阵」双通道编辑（文本通道保留科学计数法）。
- **输入 / 输出节点**：显示为 `#名称`，默认按 `X Y Z A B C …` 命名，双击改名且名称强制唯一。
- **函数（打包复用）**：框选一组节点后点工具箱里的「＋ 打包选中」，即可封装成函数——选中的输入节点留作参数来源，其余节点被一个调用节点取代；函数出现在工具箱下方的「函数」栏，拖出来就能复用。调用节点在检查 / 导出时先宏展开成平图，**W 按展开后的节点数计**，评分口径不变；函数自身的 W 也只统计展开后真正新增的节点（参数是透传，对应的输入节点不计权重）。节点右侧小三角里可以「打包为函数…」「展开为节点」「函数信息…」；函数库存在浏览器本地（localStorage），所有关卡共用。
- **数值面板（右侧栏）**：单击画布上的任意节点，右侧会显示它的精确数值；**输入节点 in 与常数节点 const 可直接按位编辑**，其余节点（含中间值与输出 out）只读，方便查看计算过程。输入 / 常数节点框内也会显示简略数值。
- **七段管数字字体**：数位矩阵与状态栏数字使用本地 DSEG7 字体（`site/fonts/`，SIL OFL 1.1），中文与符号自动回退到系统字体。
- **结构校验**：悬空端口、成环、输入节点数量、输出项数、常数合法性、未使用节点、官方上限兼容性，一键「运行检查」。
- **闯关系统**：所有关卡默认解锁，每关的画布各自独立持久化；通关条件是数值评测全部通过且 `W < 2B`，按 W 给 1–3 星。关卡列表只显示星级与最佳 W（不再展示分数）。
- **剩余权重**：顶栏实时显示 `B − W`，取负时变红，随时盯住预算。
- **题面面板**：右上角「题面」按钮打开可拖动、可关闭的悬浮窗，只显示**当前关卡**的输入输出与题目（内置 KaTeX 渲染积分、分段函数等公式）；所有关卡共用的机器规格与限制放在右上角「？」帮助里。
- **数值评测**：结构通过后按官方测试输入逐组求值，用 72 位定点（原生 BigInt）复现 checker 的 `+ − × S T E Q` 语义，判定 `|z−y| ≤ 1e-45·max(1,|y|)`，并给出通过组数与最大相对误差。
- **手动求值**：顶栏「求值」按钮与实时求值同一套语义（同样按官方精度与范围校验），但不设规模上限、分片执行并让出事件循环，按钮上实时显示进度；算完把结果塞进同一个数值面板，超大图调试时不必等实时求值。
- **标准格式互转**：按拓扑序自动重新编号，导出题面要求的 `N / 指令 / OUT k ...` 文本，导入现成 DAG 的入口已从工具栏移除，需要时在浏览器控制台执行 `showImport()` 调出（导入后自动排版，见「导入时的自动布局」）。
- **关卡骨架**：16 个任务 + 沙盒，按难度排序——3 个自制热身关（求和 / 取反 / 相乘）→ 连续数学 9 关（T1）→ 离散数学 4 关（T2：取整 / 取模 / 最大公约数 / 素性判定），含基准 B、输入输出要求与提示思路；星级只看 W：`W ≤ B` 三星，`≤ 1.5B` 两星，`< 2B` 一星。
- **编辑体验**：撤销/重做、复制/粘贴/原地复制、框选、网格吸附、localStorage 自动保存。

## 本地运行

需要一个静态服务器（ES module 不能从 `file://` 加载）：

```powershell
cd site
python -m http.server 5188        # 或 npm run dev / npx serve .
```

然后打开 http://localhost:5188/ 。

## 部署

### GitHub Pages

仓库自带 `.github/workflows/pages.yml`：推送到 `main`/`master` 后先跑单测，再把 `site/` 作为 Pages 产物发布。首次需要在仓库 Settings → Pages 里把 Source 设为 **GitHub Actions**。

也可以不用 Actions：把 `site/` 的内容直接放到 `docs/` 目录，然后在 Settings → Pages 选择 `main` 分支的 `/docs`。

站点全部使用相对路径，因此发布在 `https://<user>.github.io/<repo>/` 这种子路径下也能正常工作。

### Cloudflare Pages

- 连接 Git 仓库，**Build command 留空**，**Build output directory 填 `site`**。
- 或者直接手动上传：`npx wrangler pages deploy site`。

## 导入时的自动布局

从标准 DAG 文本导入（或生成参考答案）时节点还没有坐标，`js/core/graph.js` 的 `autoLayout()` 会跑一遍简化版 Sugiyama：

1. **分层**：节点的深度 = 到输入的最长路径，同一层的节点排在同一条横带上；
2. **层内排序**：重心法（barycenter）上下往返扫描，把有父子关系的节点排到相近位置以减少交叉（层数 > 400 时扫 2 轮，否则 4 轮）；
3. **拆行**：一层节点太多就切成若干行，行宽按该层自身的宽度自适应（目标是一层大致成「8 行高」的横条）——否则一个几百节点的输入层会把整张图撑成几万像素宽；
4. **行内定 x**：行内先按端口间距紧凑排开，再把**整行**平移到「父节点 x 的中位数」处。整行平移（而不是逐节点对齐）保证偏移不会被逐行放大，连线尽量竖直；输入 / 常数行没有父节点，统一从左边缘开始；
5. **折列**：行序列太长时蛇形折成若干竖列，**折点选在割边最少的地方**（差分数组算出每个行边界的跨界边数，在均分位置 ±25% 内挑割边最少的那一行），跨折点的长连线因此最少；
6. 整块**居中到原点**。

列数在 `1 … min(16, 行数)` 里按成本挑：

```text
成本 = 平均连线长度（以行高为单位）
     + 40 · max(0, ln(宽高比 / 2.2), ln(0.62 / 宽高比))
```

即「连线短」优先，宽高比只做「别太扁 / 别太瘦」的软约束。深链会被折成接近方形，中等规模的图则往往保留一条竖直主干。

`autoLayout({ cols })` 可强制列数，`{ perRow, rowRatio, colGap, rowGap }` 用来调参；`tools/bench_layout.mjs` 是配套的布局质量评估脚本：

| 图 | 节点 | 画布 | 宽高比 | 平均连线 | 中位连线 | 长连线(> 4 行)占比 |
|---|---:|---:|---:|---:|---:|---:|
| ans1 | 44 | 1077 × 1292 | 0.83 | 8.9 行 | 4.8 行 | 55% |
| ans4 | 116 | 3479 × 1662 | 2.09 | 13.7 行 | 5.1 行 | 60% |
| ans5 | 188 | 2798 × 2328 | 1.20 | 14.2 行 | 5.6 行 | 61% |
| ans6 | 740 | 6425 × 8396 | 0.77 | 35.9 行 | 10.5 行 | 77% |
| ans7 | 1696 | 10169 × 12836 | 0.79 | 66.6 行 | 51.3 行 | 98% |
| ans8 | 6331 | 13720 × 12802 | 1.07 | 88.1 行 | 15.8 行 | 92% |
| ans9 | 510 | 7726 × 6250 | 1.24 | 41.1 行 | 16.5 行 | 78% |

连线长度以「行高 = 节点高 + 行间距」为单位。长连线占比高是因为这些图本身就有大量跨层连线（ans7 有 30% 的边跨 3 层以上，最远的跨 119 层），布局只能保证「就近」而消不掉它们。
耗时：1696 节点约 35 ms，6331 节点约 115 ms，6 万节点约 0.5 s。

## 评分模型

本题硬约束只有**加权节点数 W** 与结构合法性，**没有运行时间限制**：

| 指令 | I | C | + | − | × | S | T | E | Q | OUT |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 权重 | 1 | 1 | 1 | 1 | 4 | 9 | 9 | 12 | 7 | 0 |

系数 `f(W) = 1 (W ≤ B)； (2B − W)/B (B < W < 2B)； 0 (W ≥ 2B)`，任务得分 = 分值 × f(W) 向下取整。
游戏内只用星级表达同一件事：`W ≤ B` 三星、`≤ 1.5B` 两星、`< 2B` 一星，界面不再展示分数。关卡分两组：连续数学 9 关（T1）与离散数学 4 关（T2）各 100 分，热身关 0 分。

## 数值评测

「运行检查」在结构通过后会自动做一次数值评测：

- **实数实现**：`js/core/bigreal.js` 用原生 `BigInt` 表示 `v = x·10^72`（对应 C++ 的 8 个 1e9 肢体）。乘法 `(a*b)/10^72`、除以小整数、解析 `C` 常数都向零截断，与 `bigreal.hpp` 的 `shiftDown` / `divSmall` 语义逐位一致。
- **节点语义**：与 checker 逐条对齐——所有节点都求值（含未被 `OUT` 引用的节点）；中间值 `|v| ≤ 1e60`，`S/T` 自变量 `|x| < 1e6`，`E` 自变量 `|x| < 100`，`Q` 自变量非负，常数 `|c| ≤ 1e6`。
- **判定**：`|z − y| ≤ 1e-45 · max(1, |y|)`。
- **参考值**：不在浏览器里重写 oracle。`node tools/gen_vectors.mjs` 调用题面自带的 `build/oracle_probe.exe`，把 9 个任务的官方输入与高精度参考输出固化到 `site/data/vectors.json`，前端检查时按需加载。T2 四关用 `gen_discrete_vectors.mjs`、热身关用 `gen_warmup_vectors.mjs` 生成，三个脚本不会互相覆盖。
- **实测**：9 个官方 std 图全部通过全部测试组；最重的 task8（6331 节点 × 23 组）约 0.2 s，求值按组让出事件循环，不会卡住界面。

> 与 C++ 的唯一差异：牛顿迭代的初始种子在 C++ 里用 `long double`、在 JS 里用 `double`，两者相差约 1e-20，最终落在相差约 1e-70 的定点不动点上——比 1e-45 的容差小 25 个数量级，不影响评测结论。
